MiraBridge for Windows 帮助

MiraBridge 将 Windows 电脑暴露为 Mac Agent 的远程原生工具执行环境。Agent 推理始终在 Mac；Windows 只执行结构化操作。

2.0.0-rc.7 未代码签名。SmartScreen 可能显示“未知发布者”。只从 官方 GitHub Release 下载，并核对同一 Release 的 SHA-256 清单。

十分钟首次设置

  1. 运行 Setup，打开 MiraBridge。
  2. 保留默认允许目录，点击“安装 / 一键修复”，批准一次 UAC。
  3. 进入连接 Mac，点击复制整条命令，把 ~/.local/bin/mirabridge pair create 交给 Mac 上的 Codex。
  4. 把 Mac 生成的请求码粘贴到 Windows，点击授权并生成响应。无需手动配置 SSH 文件或输入主机指纹。
  5. 点击复制完成命令，把整条 ~/.local/bin/mirabridge pair accept … 命令交回 Mac 上的 Codex。

四个页面分别做什么

  • 总览：确认是否可以工作，并查看连接、活跃 Job、存储和已开放能力。
  • 连接 Mac：完成两段配对码的往返复制，并撤销不再使用的 Mac。
  • 权限与目录：控制允许目录、桌面、回收站扫描和本地网页验收。
  • 工具与维护：安装可选生产力工具、检查更新、生成脱敏诊断和卸载。

状态不是 Ready

  • OpenSSH：点击“一键修复”。MiraBridge 只管理有标记的 SSH 配置块和 LocalSubnet 防火墙规则；发现 AllowUsers/DenyUsers 冲突会安全停止。
  • Worker：确认应用目录内 runtime\node\node.exe 和 runtime\worker\index.cjs 存在，再点击修复。
  • Host fingerprint：不要跳过 Mac 的实时 keyscan 匹配。配对码不是密码，也不替代主机身份校验。

Windows 地址变化

如果 DHCP 为这台电脑分配了新的主机名或 IP，请保留原配对，并在 Mac 上执行 mirabridge node reconnect windows-main --host <新主机名或 IP>。只有原固定主机指纹与真实 Worker 握手都匹配时，MiraBridge 才会接受新地址；否则会恢复旧地址。切勿通过删除 known_hosts 绕过校验。

可选工具

优先使用“工具与维护”页的 WinGet 一键安装。若 WinGet 缺失，请只使用官方来源：Git、PowerShell、Python、Node.js、.NET、FFmpeg。MiraBridge 不安装或升级任何显卡驱动。

安全与数据

默认管理员路线不等于无限文件访问：文件工具仍受 allowed roots、Desktop 能力、CAS 和审批约束。回收站清空需要即时扫描凭证。应用使用分架构的 Velopack 目录（x64 为 %LOCALAPPDATA%\MiraBridge.Windows，ARM64 带 .ARM64 后缀），持久 Worker 数据保存在 %LOCALAPPDATA%\MiraBridge。日志按 Worker 保留与 10 GiB 配额策略清理。卸载默认保留配置与任务数据；完全卸载必须明确选择。

报告问题

先在维护页生成脱敏诊断并审阅内容，再打开 GitHub Issue 手动提交。应用不进行后台遥测。
